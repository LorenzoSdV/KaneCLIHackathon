01 / The loop

A spec becomes
a gate you can see.

Each feature gets its own worktree and acceptance contract. Kane runs the contract in a real browser; the merge waits for the complete suite.

STEP 01

Start from requirements

Kane assurance turns the PRD into use cases and runnable acceptance tests. A person reviews both checkpoints before coding starts.

STEP 02

Build features in parallel

Codex agents work in separate Git worktrees. Each change must pass its contract, including core and already-merged behavior.

STEP 03

Prove the merge again

After integration, the full contract runs again. A green feature branch alone is not enough to call the combined app done.

03 / The build

AI writes code.
Tests hold the line.

Codex CLI builds each feature in an isolated worktree and gets a concrete Kane failure report when its contract does not pass. A separate contract agent uses Kane assurance to shape requirements into use cases and tests, with human approval at both checkpoints.

The orchestrator coordinates worktrees, gates, merges and the live event dashboard. Kane recordings make successful browser checks quick to replay; every merge still has to pass the complete suite.

BUILT WITH OPENAI, TESTED WITH KANE CLI.

Round 2 status

The C+D run completed. C remained unmerged because its core past-date contract failed on a timezone mismatch. D passed 24/24, though an orchestrator bug included comments tests outside D’s scope. Holding the merge until those contract and scope issues are resolved is the intended gate behavior.
